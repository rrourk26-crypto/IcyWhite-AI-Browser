RUNTIMES: ONE FOLDER PER llama.cpp BUILD, PICKED AUTOMATICALLY (new)
--------------------------------------------------------------------
You can keep several llama.cpp builds side by side, for example the NVIDIA CUDA one and a CPU-only one, each in its
own folder (llama-server.exe + all its .dll files) inside a folder named  runtimes  next to the app:
    runtimes\llama.cpp-GPU-NVIDIA CUDA\llama-server.exe  ...
    runtimes\llama-cpu\llama-server.exe  ...
Folders up to three levels deep are searched, "models" folders are skipped. Keep them somewhere else? Press
"Runtimes folder..." in Settings > Local model and pick the folder that holds them (the choice is remembered).
IcyWhite reads the files in each folder to tell what it is (ggml-cuda.dll = NVIDIA CUDA, ggml-vulkan.dll = Vulkan,
ggml-hip.dll = AMD, ggml-sycl.dll = Intel, only ggml-cpu-*.dll = CPU) and checks this PC's graphics card:
    NVIDIA card (and a driver new enough)  -> the CUDA runtime
    AMD card        -> HIP if you have it, otherwise Vulkan, otherwise CPU
    Intel Arc card  -> SYCL or Vulkan, otherwise CPU        (Intel built-in graphics -> CPU)
    no graphics card / nothing fits         -> the CPU runtime
Settings > Local model > Runtime shows what was found and what is being used, and lets you pick one by hand.
If an automatically chosen GPU runtime cannot start (missing DLL, no usable GPU), IcyWhite switches to the CPU
runtime once and tells you. Running out of memory is NOT switched silently: lower GPU layers or the context size.
A "models" folder inside a runtime folder is used for models too. The old layouts (./llama, files next to main.js)
still work. For the installer, ./runtimes is copied into resources\runtimes (models, .gguf and .bat files are left out).

BUILD THE .EXE  (on Windows, in this folder)
  1. npm install
  2. Put llama-server.exe + all its .dll files here (flat, in ./llama, or in "llama.cpp-GPU-NVIDIA CUDA").
  3. npm run build:win        -> dist\IcyWhite-Setup-<version>.exe  (installer)
     npm run build:portable   -> single portable .exe (slow to start: it unpacks ~1 GB of CUDA files each launch)
     npm run build:dir        -> dist\win-unpacked\ folder, runs without installing (best for a USB drive / zip)
  The "prepare:llama" step gathers the llama files into ./llama and stops with a message if llama-server.exe is missing.
  Do not put the models in the app folder before building.

If it will not start: open Settings > Local model > Server log. Common fixes: a missing .dll next to llama-server.exe,
"out of memory" (lower GPU layers or context size), or a model that needs a newer llama.cpp build.

LOCAL SERVER SETTINGS, DAILY FACT LINKS, APPS ON EVERY MODEL (v27)
------------------------------------------------------------------

streams replies straight through. IcyWhite's own pages always work whatever CORS rule you pick.

If you type an embedding model name (LM Studio / Ollama with an embedding model loaded) BEFORE adding documents, passages are also ranked by meaning and the two rankings are combined. If the server cannot embed, it quietly falls back to keywords. The built-in local model cannot embed.
- "Use these documents when answering" switches it off per chat. Removing a document or deleting the chat deletes its index. A "Search" box in the dialog lets you test what would be found.
- Scanned PDFs (no text layer) are not supported here; attach those with the paperclip so a vision model can look at the pages.

v36 - AUDIO INPUT
- Attach a sound file (mp3, wav, m4a, ogg, flac, webm...) with the + button, or press the 🎙 button next to it to record a clip (press again to stop). The clip is converted on this computer to 16 kHz mono WAV and sent to the model as an audio part; you can play it back in the chat.
- Needs an AUDIO-CAPABLE model plus its mmproj file in the same folder (for example Qwen2-Audio, Voxtral, Ultravox, Qwen2.5-Omni). The Hugging Face hub's "vision" checkbox downloads that mmproj file too. The app asks llama-server what it can do: if the loaded model cannot hear, attaching is refused with a plain message. With LM Studio / Ollama it just tries.
- Limits: 5 minutes per clip; many audio models only listen to the first 30 seconds (the chip warns). Audio from earlier messages is not re-sent, which saves context.
- Ordinary models cannot hear audio; for dictation into the message box keep using the Voice settings (Whisper).

v38 - LIVE CHAT: WAKE WORD + SPEAK OVER IT
- Settings > Voice > Live chat. Wake word is ON and set to "computer" (change it to any word or short phrase). Press Live chat: it waits ("Waiting for “computer”…"). Say "computer", then talk normally (you can say it in one breath: "Computer, what's the capital of France?"). A soft sound confirms it heard you.

PASSWORD MANAGER (new)
----------------------
Click the key button next to the star in the toolbar (or Tools menu > Passwords, or Ctrl+Shift+K).
  * First use: choose a master password. All saved logins are encrypted with it (AES-256-GCM, key from scrypt) in the file
    icywhite-vault.json inside the app's data folder. The master password is never stored: if you forget it the logins
    cannot be recovered (the Passwords window offers "Forgot it?" to start a new empty vault; the old file is kept, renamed).
  * Saving: sign in to a website and a bar under the toolbar asks "Save the password for ...?"  (Save / Not now / Never for this
    site). If the password changed for a saved user it offers "Update". Nothing is offered in InPrivate windows or when the
    login failed.
  * Filling: click a user name or password field on a login page and a small menu offers your saved logins for THAT site
    (the same address only; "www." is ignored; https logins are never offered on http pages). One click fills it - nothing
    is filled without a click unless you turn on "Fill a login as soon as a page loads" in the password settings.
    On sign-up forms the menu offers "Suggest a strong password".
  * The key button shows a green dot when a saved login is available for the open tab, an amber dot when the vault is locked.
  * The vault locks itself after 15 minutes (changeable), with "Lock now", and when IcyWhite closes.
  * Import / export CSV (Chrome, Edge, Firefox, Bitwarden, 1Password). Exports are NOT encrypted; delete them after use.
  * Your existing chats, settings, logins to websites (cookies) and everything else are untouched; this feature only adds files.
  Limits: login forms inside iframes are not detected; two-step logins (user name page, then password page) fill the password only.
Files: password-manager.js (vault), js/passwords-ui.js + css/passwords.css (window and save bar), the page-side code at the end
of project-preload.js, and small hooks in main.js, preload.js and browser.html. Tests: npm test (tests/password-manager.test.js).
